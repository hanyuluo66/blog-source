# 11.15 学习周报

这一周的主线只有一件：**把"陪伴"从一个会定时说话的程序，做成一个能长大的系统。**

顺带做了两个小工具，写了两道洛谷题的错因分析，还踩了几个能记一辈子的坑。

## 一、立项：为什么重做

原来的 `companion` 服务能做到"每隔 30~60 分钟主动说一句"，但它有个根本缺陷：

> **它不知道你在干什么。**

所以它只能说"在忙吗""喝口水"这类谁都能说的话。要让它说出"这题卡了七分钟了吧"，
它得先知道"你在刷题""同一道题七分钟没换过"。

于是重新立了一个项目：`steward`（陪伴总控）。

### 1.1 三个设计决定（这周最重要的收获）

**① 总控只做三件事**

```
① 收集：所有插件的 observe() 汇总到一块"状态黑板"
② 粗筛：便宜的规则判断"现在值不值得考虑开口"
③ 决策：只有通过粗筛才调模型
```

不做截屏、不判断活动、不写人格。**它一旦开始干具体活，就会变成谁都改不动的怪物。**

**② 插件之间不许互相 import**

只认一个契约文件 `contract.py`：

```python
class Capability:
    name = ""                            # 黑板上独占的栏位名

    def observe(self) -> dict: ...       # 我看得到什么
    def tools(self) -> dict: ...         # 我能被调用什么
    def tick(self, board) -> None: ...   # 我的周期工作
```

为什么必须这样：插件互相 import 之后，改 A 会崩 B，而且**没法并行开发**——想交给多个智能体分工，就只有这一条路。

**③ 全项目只有一个地方调大模型**

前几周踩过的坑：五个服务各自调 LLM，一个 key 没钱，五个一起哑，成本还乘五。

```
插件：负责"感知"和"执行"（便宜、确定性）
总控：负责"决策"（唯一调模型的地方）
```

### 1.2 三个里程碑

| | 内容 | 结果 |
| --- | --- | --- |
| M0 | 契约 + 空总控 + 黑板 | ✅ 黑板每 5 秒刷新一次 |
| M1 | `screen_eye` 读前台窗口 | ✅ 用 ctypes，零依赖 |
| M3 | `activity` + `persona` 并行开发 | ✅ 114 项自测全过 |
| M2 | 接模型 + 发 QQ | ✅ **她真的开口说了** |

### 2.2 最有价值的部分：它们互相抓问题

这部分比我预想的更值钱——三个 agent 不只是写完交差，都抓到了别人的毛病：

**① verifier 抓到一个真 bug**

> 8954 上并排挂着两个 steward，`allow_reuse_address` 让它们同时 LISTENING，
> 请求在两块独立黑板之间轮转 → ticks 乱跳。

这是 `socketserver` 的默认行为：Windows 上 `SO_REUSEADDR` 允许多个进程绑同一端口，
**不报错，安静地变成两个总控**。

修法：

```python
class ExclusiveServer(ThreadingHTTPServer):
    allow_reuse_address = False   # 第二个实例直接 bind 失败
```

验证：

```
第二个实例 → 端口 8954 已被占用：[WinError 10048]
最终 LISTENING: 1 行
```

**② dev-screen 报告了我的文件里的遗留**

它发现自己改不了 `service.py`（不在它的范围），没有偷偷改，而是写清了位置：

> `service.py` 第 142 行仍引用 `screen.get("guess")`，而该字段我这轮删了。
> 建议集成时顺手删掉；README 第 89 行的描述也过时了。

**这就是文件边界该有的效果：越界需求变成一条消息，而不是一次静默的坏改动。**

**③ dev-persona 自己报了同类残留**

### 2.3 我自己犯的错（值得记）

我用假数据验证"游戏场景心情对不对"，得出结论"判断错了"，差点去找 dev-persona 算账。

实际是**我的仿真写错了**：

```python
activity.tick(board)     # 只算自己的缓存，不写黑板
```

真实总控是 `observe()` 之后才 `board.update_owned()`。改成先 `board["activity"] = activity.observe()`
再喂给 persona 就对了。

## 四、手机上的她：能脱离电脑跑

### 4.1 为什么要在手机上

原来靠电脑 + ADB 遥控手机，电脑一关就没了。要在手机上独立跑，只能进 Termux。

现在的样子：

```
小米 10S（Android 13 · root）
└─ Termux + Python 3.14
   └─ 小鲸鱼服务 (127.0.0.1:8931)
      ├─ 模型：手机直连，2 秒出话
      ├─ 手机操作：su → input / uiautomator / screencap
      ├─ 白名单：抖音 / B站 / 微信 / QQ
      ├─ 记忆：本地 SQLite
      └─ 语音：TTS 朗读 + 浏览器语音识别
```

### 4.2 三个能记一辈子的坑

**① `app_process` 链接失败**

```
CANNOT LINK EXECUTABLE "app_process": cannot locate symbol "Xzs_Construct"
 referenced by "/system/lib64/libunwindstack.so"
```

原因：Termux 的 `LD_LIBRARY_PATH` 污染了系统命令，`uiautomator` 底层的 `app_process`
加载到了 Termux 的库。读屏完全失效。

**② 但把环境清空更糟**

第一版修法是 `env -i` 给一套干净环境，结果：

```
mkdir: '/data/local/tmp/dalvik-cache': Permission denied
```

因为丢了 `ANDROID_DATA`、`ANDROID_ROOT` 这些变量，dalvik 起不来。

**③ 最终解法：只摘掉链接器变量，并经过系统 shell**

```python
argv = ["/system/bin/sh", "-c",
        "LD_LIBRARY_PATH= LD_PRELOAD= /product/bin/su -c " + shlex.quote(command)]
```

改完立刻就对了——她读出了锁屏上的内容。

### 4.3 三次实测（它判断得比"能不能"更重要）

**① 读屏**

> 看到了爸——手机管家弹了个拦截通知，说拦住了USB装的Termux，现在还在锁屏上，充电41%。

（准确，连通知内容都对）

**② 陪刷抖音**

> 爸，尴尬了——抖音压根没刷成，停在登录页了，要你手机号一键登录，底下还一个"未勾选"的协议框。
> 我滑了两下全是这个页面，没一条视频。
> **要我把那个协议勾了、点一键登录不？还是你自个儿弄？**

它真的打开抖音 → 滑了 2 下 → 读屏 → 发现是登录页 → **没有擅自勾协议**，先问。

**③ 白名单拦截**

> 爸，设置不在我白名单里，我开不了——我只能开抖音、B站、微信、QQ这几个。

### 4.4 还有两个坑

- **MIUI 安装拦截**：`adb install` 会弹确认框，`INSTALL_FAILED_USER_RESTRICTED`。
  改用 root：`su -c pm install -r -g`，全程无人干预。
- **`su 10268` 建不了 socket**：从 root 降到应用 uid 后 SELinux 域不对，
  `PermissionError: [Errno 13]`。开机自启改用 **Termux:Boot**（本身就是应用身份）。

## 五、顺手做的两个小工具

### 5.1 任务栏电量控件

需求：右下角常驻显示鼠标/键盘电量。

数据源出乎意料地简单——Windows 有个设备属性：

```
{104EA319-6EE2-4701-BD47-8DDBF425BBE5} 2    ← DEVPKEY_Bluetooth_Battery
```

一次属性查询 50 毫秒，不用连蓝牙、不用装驱动。

结果：**鼠标只有 2% 电量**（该充电了），键盘读不到。

理由是硬件决定的：

| 设备 | 连接方式 | 能读吗 |
| --- | --- | --- |
| AULA SC580SE 鼠标 | 蓝牙 LE | ✅ 2% |
| MCHOSE G87 V2 键盘 | **2.4G 接收器** | ❌ Windows 不提供 |

四个坑：

1. **全设备扫描要几分钟**——90 多个 HID 节点逐个查属性。收窄到只查蓝牙后 9 秒。
2. **PowerShell 5.1 把无 BOM 的 UTF-8 当 GBK 读**，中文全乱码。
3. **杀旧实例差点把自己杀了**——用 `CommandLine -match 'battery_widget'` 筛选，
   结果匹配到正在执行这条命令的 pwsh 自己（命令行里也含这个字符串）。
4. **Win11 新图标默认折进隐藏区**，要改注册表 `IsPromoted=1` 再重启 explorer。

中间还试过一条死路：PowerShell 5.1 读不了 BLE 的 `GattReadResult.Value`
（`__ComObject` 转不成 `IBuffer`，连 `Add-Type` 引 `Windows.winmd` 也失败）。
最后发现**根本不用走 GATT**，PnP 属性里就有。

## 六、C++：这周的两道题

### 6.1 P5729 工艺品制作：`= {0}` 是摆设

```cpp
int a[w][x][h] = {0};   // w/x/h 是变量 → 变长数组
```

两个问题叠在一起：

1. 变长数组不是标准 C++，只是编译器扩展；
2. **更致命：变长数组上的 `= {0}` 会被编译器直接忽略**，数组里是栈上残留的值。

证据（2×2×2 涂一块，正确 7）：

```
你的输出：4          ← 8 个格子有 4 个"一开始就是 1"
连跑 6 次：全是 4    ← 错得很稳定，所以本机永远测不出来
```

修法：长度写死。

```cpp
int a[25][25][25] = {0};   // 死数字才会真的清零
```

### 6.2 第二个 bug：统计循环放错位置

```cpp
for (i = 0; i < q; i++) {
    ...涂色...
    for (...) 数一遍       // ← 每涂一次就数一遍，累加到 sum
        sum++;
}
```

涂 q 次就数 q 遍、加 q 次。正确做法是涂完再数一次。

三版对照（证明是两个**独立**的 bug）：

| 用例 | 期望 | 原版 | 只修数组 | 全修 |
| --- | --- | --- | --- | --- |
| 1×1×1 全涂 | 0 | 0 ✅ | 0 ✅ | 0 ✅ |
| 2×2×2 涂角落 | 7 | **4** ❌ | 7 ✅ | 7 ✅ |
| 2×2×2 涂对角两块 | 6 | **7** ❌ | **13** ❌ | 6 ✅ |
| 3×3×3 涂 2×2×2 | 19 | **8** ❌ | 19 ✅ | 19 ✅ |
| 2×2×2 同块涂两次 | 7 | **8** ❌ | **14** ❌ | 7 ✅ |

"只修数组"那一列很值钱：q=1 全对，q≥2 全错——说明统计那个 bug 没被数组掩盖。

### 6.3 P1614 爱与愁的心痛：初值 301 太小

题目数据范围（末尾一行）：`0 ≤ m ≤ n ≤ 3000`，`1 ≤ aᵢ ≤ 100`。

所以 m 个数加起来最大能到 **3000 × 100 = 300000**，而代码写的是：

```cpp
int min = 301;   // ← 只要真答案超过 301，min 永远不更新
```

实测 7 组：

| 用例 | 正确答案 | 你的输出 |
| --- | --- | --- |
| 样例 `5 2 / 1 2 3 4 5` | 3 | 3 ✅ |
| `3 2 / 200 200 200` | 400 | **301** ❌ |
| `10 10` 全是 100 | 1000 | **301** ❌ |
| 恰好 301 | 301 | 301 ✅ |
| **302**（只比初值大 1） | 302 | **301** ❌ |
| `m=0` | 0 | 0 ✅ |

注意"301 对、302 错"这一对：**这就是初值设太小的典型症状**，边界上蒙对了，一越界就露馅。

固定套路：

```cpp
int ans = 1e9;   // 求最小 → 初值要比所有可能答案都大
int ans = 0;     // 求最大 → 初值很小（且答案非负）
```

### 6.4 顺带搞清：int 和 long long 的上限

| 类型 | 字节 | 最大正数 | 大约 |
| --- | --- | --- | --- |
| `int` | 4 | 2147483647 | 21 亿 |
| `long long` | 8 | 9223372036854775807 | 922 亿亿 |

最重要的一点是**超了不会报错**：

```cpp
int a = 2147483647;
cout << a + 1;        // 输出 -2147483648

100000 * 100000 当 int    → 1410065408     ← 错，还看不出错
100000 * 100000 当 long long → 10000000000  ← 对
```

只要答案可能超过 21 亿就上 `long long`：阶乘、斐波那契、前缀和、大数相乘。

还有个细节：**运算时就要是 long long，不能最后才转**。

```cpp
long long c = a * b;              // ✗ 先按 int 算完（已经错了）再存
long long d = (long long)a * b;   // ✓ 先转一个，整个运算按 64 位算
```

## 八、踩坑总表

| 坑 | 表现 | 教训 |
| --- | --- | --- |
| VLA 的 `= {0}` 不生效 | 数组没清零，答案稳定地错 | 长度写死才会真清零 |
| 统计循环放错层 | 涂 q 次数 q 遍 | 累加类操作要想清"每轮做什么" |
| 求最小值初值太小 | 边界上对、越界就错 | 初值要比所有可能答案都大 |
| `int` 溢出 | 静默变负数 | 超过 21 亿上 `long long` |
| 端口能被两个进程同时绑 | 两个总控、黑板不共享 | `allow_reuse_address = False` |
| 配置展开顺手换了斜杠 | URL 坏成 `no host given` | 只换该换的占位符 |
| 我自己的测试仿真写错 | 差点冤枉队友 | 先证明测试是对的，再信测试结论 |
| `LD_LIBRARY_PATH` 污染 | `app_process` 链接失败 | 只摘链接器变量，别清空全部 |
| 清空环境更糟 | dalvik 缓存建不出来 | 保留 `ANDROID_DATA` 等 |
| `su` 降权后 SELinux 域不对 | 建不了 socket | 改用 Termux:Boot |
| 杀进程匹配到自己的命令行 | 命令把自己干掉 | 用 PID 排除自己 |
| Chromium cookie `v20` | 外部解不开 | App-Bound 是安全机制，不是 bug |
